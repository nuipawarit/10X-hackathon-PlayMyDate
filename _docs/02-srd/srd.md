# SRD: System Requirement Document

## 1. System Overview

ระบบหาคู่ออนไลน์ที่เปลี่ยนประสบการณ์การหาคู่จาก "การปัดและตัดสินจากรูป" เป็น "การรู้จักกันผ่านกิจกรรมและภารกิจร่วมกัน" โดยระบบจะ:

- ให้ผู้ใช้สร้างตัวตนในรูปแบบที่สบายใจ (ไม่บังคับเปิดเผยรูปหรือข้อมูลจริงตั้งแต่แรก)
- จับคู่ผู้ใช้จากสไตล์การเล่นและความสนใจ แทนการตัดสินจากรูปหรือข้อความอย่างเดียว
- จัดกิจกรรมหรือภารกิจสั้นๆ ให้ทั้งสองฝ่ายทำร่วมกัน เพื่อลดความ awkward ในการเริ่มคุยและช่วยให้รู้จักกันลึกขึ้น
- ค่อยๆ ปลดล็อกข้อมูลจริง (รูป อาชีพ ชื่อ ฯลฯ) เมื่อทั้งคู่ผ่านเกณฑ์ความสนิทที่กำหนด
- เชื่อมจากคุยในแอปไปสู่การนัดเจอจริง โดยแนะนำสถานที่หรือกิจกรรมเดท และจัดการเรื่องค่าใช้จ่ายเดทอย่างโปร่งใส

ระบบนี้มุ่งเน้นคุณภาพการจับคู่มากกว่าปริมาณ และช่วยลดความกดดันในการเริ่มบทสนทนาผ่านกิจกรรมที่ออกแบบมาเพื่อให้ผู้ใช้รู้จักกันอย่างเป็นธรรมชาติ

## 2. Functional Requirements

### 2.1 การสร้างและจัดการตัวตน (Profile Management)

- ผู้ใช้สามารถสร้างโปรไฟล์โดยไม่บังคับให้เปิดเผยรูปหรือข้อมูลจริงตั้งแต่แรก
- รองรับการสร้างตัวตนในรูปแบบที่หลากหลาย เช่น ใช้เสียง ตัวแทน หรือข้อมูลเบื้องต้น
- ผู้ใช้สามารถค่อยๆ เปิดเผยข้อมูลจริงเมื่อพร้อมหรือเมื่อผ่านเกณฑ์ความสนิท

### 2.2 ระบบจับคู่ (Matching System)

- จับคู่ผู้ใช้จากสไตล์การเล่นและความสนใจ แทนการตัดสินจากรูปหรือข้อความอย่างเดียว
- วิเคราะห์และจับคู่จากพฤติกรรมการเล่นกิจกรรมและภารกิจ
- จัดการสถานะการจับคู่ (Match) และความสัมพันธ์ระหว่างผู้ใช้

### 2.3 ระบบกิจกรรมและภารกิจ (Activity & Mission System)

- จัดกิจกรรมหรือภารกิจสั้นๆ ให้ทั้งสองฝ่ายทำร่วมกัน
- กิจกรรมต้องช่วยลดความ awkward ในการเริ่มคุย เช่น ทายกันว่าอีกฝ่ายกินอะไรจากคำใบ้ หรือไขปริศนาที่ต้องสื่อสารกันถึงจะผ่าน
- ติดตามความคืบหน้าและผลลัพธ์ของกิจกรรมที่ทำร่วมกัน

### 2.4 ระบบการสื่อสาร (Communication System)

- รองรับการส่งข้อความระหว่างผู้ใช้ที่จับคู่กัน
- เมื่อผ่านเกณฑ์ความสนิทที่กำหนด ระบบปลดล็อกให้ใช้ช่องทางโทรหรือวิดีโอคอล
- จัดการสถานะการสนทนาและความคืบหน้าของความสัมพันธ์

### 2.5 ระบบปลดล็อกข้อมูล (Progressive Disclosure System)

- ติดตามระดับความสนิทระหว่างผู้ใช้ที่จับคู่กัน
- ปลดล็อกข้อมูลจริง (รูป อาชีพ ชื่อ ฯลฯ) เมื่อทั้งคู่ผ่านเกณฑ์ความสนิทที่กำหนด
- จัดการสิทธิ์การเข้าถึงข้อมูลตามระดับความสนิท

### 2.6 ระบบแนะนำสถานที่และกิจกรรมเดท (Date Planning System)

- แนะนำสถานที่หรือกิจกรรมเดทที่เหมาะสมกับทั้งสองฝ่าย
- จัดการเรื่องค่าใช้จ่ายเดทอย่างโปร่งใส
- เชื่อมต่อกับร้านอาหาร/คาเฟ่และกิจกรรมเดท (สำหรับโมเดลรายได้ในอนาคต)

### 2.7 ระบบสมาชิกและการชำระเงิน (Subscription & Payment System)

- จัดการค่าสมาชิกและโมเดลรายได้
- รองรับการชำระเงินสำหรับค่าสมาชิกและค่าใช้จ่ายเดท

## 3. Non-Functional Requirements

### 3.1 Performance

- ระบบต้องตอบสนองได้รวดเร็วในการจับคู่และแสดงกิจกรรม
- การโหลดกิจกรรมและภารกิจต้องไม่ทำให้ผู้ใช้รอนาน
- การส่งข้อความและการสื่อสารต้องมีความล่าช้าต่ำ

### 3.2 Security

- ข้อมูลส่วนตัวของผู้ใช้ต้องได้รับการปกป้องอย่างเข้มงวด
- ระบบต้องป้องกันการเปิดเผยข้อมูลจริงก่อนที่ผู้ใช้จะพร้อมหรือผ่านเกณฑ์ความสนิท
- การจัดการข้อมูลการชำระเงินต้องมีความปลอดภัยสูง
- ต้องมีมาตรการป้องกันการใช้งานที่ผิดปกติหรือเป็นอันตราย

### 3.3 Constraints

- ไม่รับประกันผลลัพธ์ความสัมพันธ์หรือการแต่งงาน
- ไม่เน้นการปัดหรือดูโปรไฟล์จำนวนมากแบบไม่จำกัด โดยไม่เน้นคุณภาพการจับคู่
- ต้องไม่เพิ่ม scope นอกเหนือจากที่กำหนดใน BRD

## 4. High-Level Components

### 4.1 Frontend

- หน้าสร้างและจัดการโปรไฟล์
- หน้าจับคู่และแสดงรายชื่อผู้ใช้ที่จับคู่กัน
- หน้าจัดการกิจกรรมและภารกิจ
- หน้าสนทนาและสื่อสาร
- หน้าจัดการการปลดล็อกข้อมูล
- หน้าวางแผนนัดเจอและเลือกสถานที่
- หน้าจัดการสมาชิกและการชำระเงิน

### 4.2 Backend

- บริการจัดการผู้ใช้และโปรไฟล์
- บริการจับคู่และวิเคราะห์ความเข้ากันได้
- บริการจัดการกิจกรรมและภารกิจ
- บริการจัดการการสื่อสาร
- บริการติดตามความสนิทและปลดล็อกข้อมูล
- บริการแนะนำสถานที่และกิจกรรมเดท
- บริการจัดการสมาชิกและการชำระเงิน
- ฐานข้อมูลสำหรับเก็บข้อมูลผู้ใช้ กิจกรรม การจับคู่ และความสัมพันธ์

### 4.3 External Services (ถ้ามี)

- บริการชำระเงิน (Payment Gateway) สำหรับค่าสมาชิกและค่าใช้จ่ายเดท
- บริการแผนที่หรือ API สำหรับค้นหาและแนะนำสถานที่เดท (อาจพิจารณาในอนาคต)
- บริการสื่อสารแบบเรียลไทม์สำหรับการโทรหรือวิดีโอคอล (เมื่อปลดล็อกแล้ว)

## 5. Data Overview

### 5.1 ข้อมูลผู้ใช้ (User Data)

- ข้อมูลโปรไฟล์พื้นฐาน (อาจไม่เปิดเผยตั้งแต่แรก)
- ข้อมูลจริง (รูป อาชีพ ชื่อ ฯลฯ) ที่จะปลดล็อกเมื่อผ่านเกณฑ์ความสนิท
- สไตล์การเล่นและความสนใจ
- สถานะสมาชิกและการชำระเงิน

### 5.2 ข้อมูลการจับคู่ (Matching Data)

- รายการผู้ใช้ที่จับคู่กัน
- ระดับความเข้ากันได้จากการวิเคราะห์สไตล์การเล่นและความสนใจ
- สถานะการจับคู่และความสัมพันธ์

### 5.3 ข้อมูลกิจกรรมและภารกิจ (Activity & Mission Data)

- รายการกิจกรรมและภารกิจที่พร้อมใช้งาน
- ประวัติการทำกิจกรรมร่วมกันระหว่างผู้ใช้ที่จับคู่กัน
- ผลลัพธ์และความคืบหน้าของกิจกรรม

### 5.4 ข้อมูลการสื่อสาร (Communication Data)

- ข้อความระหว่างผู้ใช้
- สถานะการสนทนา
- บันทึกการโทรหรือวิดีโอคอล (เมื่อปลดล็อกแล้ว)

### 5.5 ข้อมูลความสนิท (Intimacy/Relationship Data)

- ระดับความสนิทระหว่างผู้ใช้ที่จับคู่กัน
- เกณฑ์และเงื่อนไขการปลดล็อกข้อมูล
- ประวัติการปลดล็อกข้อมูล

### 5.6 ข้อมูลการนัดเจอ (Date Planning Data)

- สถานที่หรือกิจกรรมเดทที่แนะนำ
- การจัดการค่าใช้จ่ายเดท
- ประวัติการนัดเจอ
